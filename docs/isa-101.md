# ISA-101 rationale

ANSI/ISA-101.01 describes high-performance HMIs: displays that help an
operator notice what is abnormal and act on it, rather than displays that look
like the plant. This page lists the choices this HMI makes and the reason for
each, so an integrator knows which ones to keep.

## Colour means something, or it isn't used

| Choice | Why |
|---|---|
| Process graphics are grey: grey background, grey equipment, light lines. | If everything is colourful, nothing stands out. A calm display makes the one abnormal thing obvious. |
| Colour is kept for **alarms** (priority 1 red, 2 amber, 3 teal) and **interlocks** (violet). | An operator learns that colour on a process display always needs attention. |
| The brand lime appears only in the chrome (header, navigation, focus ring), never in a process drawing. | Brand colour inside a drawing would read as state. |
| Running, open, closed and normal states have no colour. | Normal is not news. |

## State by shape, with redundant coding

- **Switching devices**: a closed breaker is filled and an open one is an
  outline. Intermediate is a diagonal and invalid is a cross. An unknown
  position is dashed with a "?".
- **Energization**: a live conductor is bright and twice as thick as a dead
  one, which is thin and grey (lines 4 px against 2 px, busbars 10 against
  5), and an unknown one is dashed. Lightness and width both carry the
  state, so it still reads when the drawing is scaled down, on a poor
  screen or in grey scale. It comes from measured voltages and switch
  positions, not from assumptions.
- **Alarm priority** is shown three ways at once: shape (◆ 1, ▲ 2, ■ 3), colour
  and the number inside. It stays readable for colour-blind users, on a
  monochrome screen and in a screenshot.
- **Alarm indication**: an unacknowledged alarm flashes (only when the user
  allows motion) and has a ring, an acknowledged one is steady, and a returned
  but unacknowledged one is an outline.
- **Turbines**: solid when producing, outline when stopped, half-filled when
  curtailed, dashed when the turbine is silent.
- **Abnormal values** in faceplates are told by weight and a marker (▸), not
  by colour.

## Values carry their quality

- Bad quality never shows a number as if it were good: it shows "?", greyed.
- A stale value (its agent is down, or the link to the hub is) is dimmed and
  marked, while the last value stays visible.
- Analog values come with a **moving analog indicator** (`AnalogBar`):
  where the value sits within its range, the normal band and the limits. That
  is faster to read than a number alone.

## Display hierarchy

| Level | Screen | Purpose |
|---|---|---|
| L1 | Overview | The whole site at a glance: export against what the wind allows, grid connection, wind, alarms by area. No control. |
| L2 | Substation single-line, wind farm | One process area, for monitoring and the usual operations. |
| L3 | Faceplates (bay, transformer, turbine) | One unit: every measurement, protection signals, commands and their interlocks. |
| L4 | Alarms, event log, trends, comms | Diagnosis and analysis. |

Every L1 and L2 element leads down to the level that explains it, and the
breadcrumb shows where the operator is. Faceplates open beside the drawing,
not over it, so the context stays visible.

## Alarms (ISA-18.2)

- The active list follows the standard's states: an alarm stays until it is
  both cleared and acknowledged.
- Analog alarms reset only past a deadband (5 °C for the transformer thermal
  alarms), so a value hovering at a limit does not chatter.
- The header always shows the count per priority, with the newest
  unacknowledged alarm in a banner, on every screen.
- Acknowledging is a separate permission from operating.
- The event log is separate from the active list and read-only.

Not yet in the demo: shelving, suppression by state and alarm flood handling.
The backend would need to support them.

## Commands are deliberate

- **Select, then confirm**: a command is selected first (permission and
  interlock are checked, and the selection expires after 30 s), then
  confirmed, then tracked step by step until the agent reports the result.
- **Every command button shows its interlock state**, without opening
  anything, and in proportion to what needs attention. An allowed command is a
  plain button with a muted "Why?". An interlocked one has the interlock
  violet frame, a padlock, "Interlocked" and a bold "Why blocked?". While the
  HMI can't trust the answer (not loaded yet, or an input is stale) it shows
  "?" and "Interlock unknown", never "allowed". The state is live: it changes
  as the plant does.
- An interlocked command says why it is blocked: the ladder view shows which
  condition stops it and what the condition reads now.
- Bypassing an interlock is a separate permission and an explicit choice in
  the dialog.

## Trends

Trend lines are grey and told apart by dash pattern, with limits drawn as
dashed reference lines. A trend shows a value's direction; colour stays
reserved for alarms.

## Texts

The backend sends identifiers, and every word comes from a dictionary. Names
follow how operators write them (CB, DS, ES, TR2), so they fit symbols and
gates.
